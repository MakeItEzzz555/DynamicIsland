### Fixes in this phase
- **Now Playing misclassification (real defect).** `sourceKind` used substring matching, so any
  third-party player whose name contains “Music” (e.g. “YouTube Music”) or “Spotify” was treated as
  Music.app/Spotify.app, got transport/seek/volume enabled, and commands were sent to — and could
  launch — Music.app. Classification is now exact (bundle id authoritative; exact name only when no
  bundle id). Tests: `MediaCapabilityParityTests.testNowPlayingClassificationRequiresExactSpotifyOrMusicIdentity`,
  `testSystemOnlySourceOffersNoTransportCommands`.
- **Missing Client ID never regresses local Spotify** (was structurally true — `MediaController`
  has no dependency on `SpotifyLibraryController` — now pinned by
  `testMissingSpotifyClientIDDoesNotRegressLocalSpotifyDetectionOrControls`: library stays
  `.needsClientID`, local detection publishes, `playpause`/`next track` reach Spotify).
- **Truthful copy.** Unconfigured state now says the *library* (queue/playlists/liked) is not
  available and that Spotify app controls still work; Settings badge “Not configured”.
- Spotify row accessibility labels were not interpolated (`"Add (item.title) to queue"`); fixed.

## 3. Gesture / Camera Mirror acceptance

Spec check of `RightWorkspaceSwipeRecognizer` + overlay routing (overlay file not modified):
horizontal → exactly one page per physical gesture (latched, momentum never pages); vertical →
`.passThrough` for the whole sequence incl. momentum; the recognizer is consulted before
`CameraMirrorScrollRoutingPolicy`, so with the mirror active horizontal still pages and vertical
passes to the native ScrollView while island-level up/down actions are muted. New tests:
`testScrollEdgeOvershootNeverBecomesPageSwipe`, `testHorizontalSwipeOverMirrorPagesExactlyOnce`.

Camera lifecycle defects found and fixed:
- **Close Mirror during an in-flight attach leaked a consumer** (camera stayed on with the mirror
  closed): the view recorded ownership only after `attachPreviewConsumer()` returned. Now
  `CameraMirrorConsumerLease` claims synchronously and releases exactly once.
- **Independent owner that joined after the mirror** was stopped by Close Mirror. `open()` now marks
  an explicit owner; the mirror only stops capture it owns. Device switching keeps ownership; an
  unexpected stop clears the explicit claim so a mirror Retry is released on close.
- Deterministic tests (fakes + gated start): close releases/stops, reopen restarts without prompt,
  concurrent acquire counts once, close-during-start race, independent owner (both orders), device
  switch, unexpected-stop retry.
- **Real camera (DYNAMIC_ISLAND_LIVE_CAMERA=1): PASS** on FaceTime HD Camera —
  `testRealCameraMirrorStartsMirrorsAndStops` (mirroring supported, mirrored=true) and new
  `testRealCameraMirrorCloseReopenAndIndependentOwner` (close stops capture, reopen restarts,
  explicit owner kept capture after mirror close, explicit close stops).

## 4. Blockers / manual

- **Spotify Web API E2E — BLOCKED.** No distributor Client ID is packaged
  (`DYNAMICISLAND_SPOTIFY_CLIENT_ID` unset) and the user’s Spotify account is not eligible to create a
  developer app (development-mode restrictions). OAuth/PKCE, queue, playlists, liked, add-to-queue
  and save/unsave are implemented and mock-tested only. UI shows “Not configured”.
- **Calendar hardened-runtime entitlement — BLOCKED (approval).** Developer ID builds need
  `com.apple.security.personal-information.calendars`; not approved, not added. Usage strings are
  present; EventKit implementation is left intact. Ad-hoc/debug builds are unaffected.
- **Timer page preview — BLOCKED (ownership).** Needs `DedicatedTimerPageView` made internal in
  `IslandRootView.swift` (not owned here); then `SettingsView.timerSection` can render it in the
  sandbox and the six pinned gaps can be removed.
- **MANUAL:** real-trackpad acceptance (one page per swipe, vertical scroll in lists/mirror page,
  scroll-edge behavior) and visual GUI review of Settings previews cannot be done from the shell.
- Open product question (not changed): whether the workspace should also return to the default page
  on every collapse (`RightWorkspaceStore.resetToDefaultPage()` exists but has no caller).
